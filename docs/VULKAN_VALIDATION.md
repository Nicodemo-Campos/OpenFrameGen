# Vulkan validation workflow

This document describes a development-time validation pass for the
OpenFrameGen Vulkan layer.

The goal is to run the Khronos Validation Layer *below* OpenFrameGen so it
can observe Vulkan commands generated by OFG itself, including command
buffers, barriers, copies, semaphores and fences.

## Prerequisites

- a recent Vulkan SDK with `VK_LAYER_KHRONOS_validation`;
- a built OpenFrameGen Vulkan layer;
- a Vulkan application that presents frames, such as `vkcube`.

On Windows, keep the normal Vulkan SDK layer discovery intact and add the
OpenFrameGen build directory with `VK_ADD_LAYER_PATH`.

## Windows PowerShell

From the OpenFrameGen repository root:

```powershell
$env:VK_ADD_LAYER_PATH = (Resolve-Path .\build\ofg-layer).Path
$env:VK_INSTANCE_LAYERS = "VK_LAYER_OPENFRAMEGEN_framegen;VK_LAYER_KHRONOS_validation"

$env:VK_VALIDATION_VALIDATE_CORE = "true"
$env:VK_VALIDATION_VALIDATE_SYNC = "true"
$env:VK_VALIDATION_THREAD_SAFETY = "true"
$env:VK_VALIDATION_REPORT_FLAGS = "error;warn"

$env:OFG_LOG_FILE = (Join-Path (Get-Location) "ofg-layer.log")

Remove-Item .\ofg-layer.log -ErrorAction SilentlyContinue
Remove-Item .\vulkan-validation.log -ErrorAction SilentlyContinue

$process = Start-Process vkcube -PassThru -RedirectStandardError .\vulkan-validation.log

Start-Sleep -Seconds 5

Get-Content .\ofg-layer.log
Get-Content .\vulkan-validation.log
```

Close `vkcube` normally after the test. If needed:

```powershell
Get-Process vkcube -ErrorAction SilentlyContinue | Stop-Process
```

## Layer ordering

On Windows, `VK_INSTANCE_LAYERS` uses semicolons between layer names.

The first layer is closest to the application. This ordering is intentional:

```text
Application
    |
    v
OpenFrameGen
    |
    v
Khronos Validation
    |
    v
Vulkan driver
```

Putting validation below OFG allows it to validate the Vulkan work injected
by the OpenFrameGen layer.

## Expected OFG result

The existing frame-copy smoke test should still contain:

```text
[OpenFrameGen] Frame copy resources ready: ...
[OpenFrameGen] First GPU frame copy submitted: ...
[OpenFrameGen] First GPU frame copy completed.
```

The application should continue rendering normally.

## What counts as a validation failure

Warnings must be reviewed, but synchronization or object-lifetime errors
associated with OFG-created resources are blockers for the synchronization
milestone.

Particular areas to inspect include:

- image layout transitions around `vkCmdCopyImage`;
- semaphore signal/wait reuse;
- command-buffer reuse;
- fence reset/reuse;
- swapchain destruction and recreation;
- queue-family and queue-handle assumptions;
- object destruction while work is still pending.

## Cleanup

```powershell
Remove-Item Env:VK_INSTANCE_LAYERS -ErrorAction SilentlyContinue
Remove-Item Env:VK_ADD_LAYER_PATH -ErrorAction SilentlyContinue
Remove-Item Env:VK_VALIDATION_VALIDATE_CORE -ErrorAction SilentlyContinue
Remove-Item Env:VK_VALIDATION_VALIDATE_SYNC -ErrorAction SilentlyContinue
Remove-Item Env:VK_VALIDATION_THREAD_SAFETY -ErrorAction SilentlyContinue
Remove-Item Env:VK_VALIDATION_REPORT_FLAGS -ErrorAction SilentlyContinue
Remove-Item Env:OFG_LOG_FILE -ErrorAction SilentlyContinue
```

Do not run development layers against anti-cheat protected online games.
Use controlled Vulkan samples during early layer development.


## Swapchain recreation test

Run the validation workflow above, then repeatedly resize the `vkcube`
window for roughly 10 to 15 seconds. Include both larger and smaller sizes.

The OpenFrameGen log should show multiple swapchain generations, for example:

```text
[OpenFrameGen] Swapchain #1 created: 500x500, ...
[OpenFrameGen] First present for swapchain #1: ...
[OpenFrameGen] Frame copy resources ready: ...
[OpenFrameGen] First GPU frame copy completed.
[OpenFrameGen] Swapchain #1 destroyed: 500x500, images=3.
[OpenFrameGen] Swapchain #2 created: 900x650, ...
[OpenFrameGen] First present for swapchain #2: ...
[OpenFrameGen] Frame copy resources ready: ...
[OpenFrameGen] First GPU frame copy completed.
```

Exact dimensions and the order of destruction versus creation can vary by WSI
implementation. The important requirements are:

- a new swapchain generation is observed after recreation;
- OFG creates a new set of copy resources for the new swapchain;
- frame copies resume and complete;
- the application continues rendering normally;
- the validation log contains no VUIDs, synchronization hazards, warnings, or
  object-lifetime errors attributable to OFG.

After the resize stress pass, close `vkcube` normally and inspect both logs
again so destruction-time validation messages are not missed.
